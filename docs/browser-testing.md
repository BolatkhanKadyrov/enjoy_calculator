# Браузерная проверка в Codex для VS Code

04.11.2026 заказчик явно разрешил перейти с недоступного Computer Use на Playwright MCP с отдельным тестовым профилем. Ранее повторялось `The browser access host is unavailable`; обход проверки URL через Windows не используется.

## Локальное подключение

- Имя в Codex: `playwright_tseh`.
- Настройки: пользовательский `~/.codex/config.toml`, только новый раздел MCP. Остальные параметры сохранены. Перед записью создана копия `config.toml.before-playwright-20261104-223007.bak` рядом с конфигурацией; она не публикуется.
- Пакет Microsoft `@playwright/mcp` закреплён на `0.0.84`; установлен в `.local/browser-tooling`, точное дерево — в локальном `package-lock.json`. Зависимости Django-приложения не изменены.
- Запуск через установленный Node.js и локальный `@playwright/mcp/cli.js`, транспорт stdio. Не создаётся сетевой MCP-сервис.
- Используется установленный Chrome в headless-режиме с включённой песочницей. Рабочий профиль пользователя не подключается. Профиль проверки — `.local/browser-profile`.
- Стартовый viewport: 1440×1000. Снимки и служебные результаты — `.local/browser-artifacts`.
- Запросы браузера настроены для `localhost`/`127.0.0.1` на портах 8000 (приложение) и 8001 (возможный отдельный QA-сервер). Эта настройка Playwright не является полноценной границей безопасности.
- Включённая запись MCP проверена командой `codex mcp get playwright_tseh --json`. Для появления новых инструментов в IDE нужно перезапустить расширение или перезагрузить окно VS Code.

## Выполненная проверка

Проверены инициализация протокола MCP, получение 25 инструментов и открытие `http://127.0.0.1:8000/`. Приложение штатно перенаправило отдельный браузер на `/login/?next=/`. Сохранён и визуально просмотрен скриншот `.local/browser-artifacts/login-desktop.png`. Закрыты только созданные проверкой вкладка и процесс MCP. Вход, отправка форм и изменение рабочих данных не выполнялись.

После перезагрузки VS Code инструменты `playwright_tseh` появились в текущем чате и были успешно вызваны непосредственно агентом. Подключение подтверждено, прежний блокер browser host снят.

Повторить проверку зарегистрированной конфигурации:

```powershell
.venv\Scripts\python.exe scripts/check_browser_mcp.py --navigate --screenshot
```

Не запускать пробу параллельно с другим клиентом `playwright_tseh`: один постоянный профиль принадлежит одному экземпляру браузера. Для параллельного QA нужен другой профиль.

Папка `.local` исключена из контроля версий; профиль содержит тестовую сессию входа, поэтому его не публикуют. На другом компьютере пакет нужно установить заново и настроить пути.

## Браузерная проверка 0.3.2

Использован отдельный сервер `http://127.0.0.1:8001/`, база `tseh_qa` и пользователь `qa-review` со случайным локальным паролем. Тестовые рецептуры и цены созданы только в QA-базе. Рабочая база `tseh` не изменялась.

- Chrome, 1440×1000: визуально проверены кнопка «Новое блюдо», поле скидки, вторичная кнопка и подсказка под ними. Метрики `text-box-trim` / `ex alphabetic` поддерживаются установленным браузером. Надписи используют общий `.button-label`, JS сохраняет эту обёртку при смене текста.
- Ширина 360 px: проверены форма скидки и ошибка при 100%. Поле и кнопка остаются на одной строке, ошибка и подсказка — ниже; `aria-describedby` связывает обе подписи с полем. Найденное переполнение grid исправлено. Дополнительно на 320 px нет горизонтального переполнения страницы; блок скидки выдерживает искусственное увеличение своего текста вдвое, кнопка растёт по высоте с переносом текста. Таблицы прокручиваются внутри своей области.
- Скидка 10%: исходные 1400 ₸ и 500 ₸ дали 1260 ₸ и 450 ₸; базовые цены остались прежними. Ожидаемые результаты заданы независимо от кода приложения.
- Редактор на 760 px: просмотрены контрастный заголовок категории, отступ стрелки, фокус поиска. Запрос «масло» оставил один вариант; ArrowDown/Enter выбрали его. Смена компонента с граммов на миллилитры запросила подтверждение очистки несовместимого количества. После подтверждения единица — `ml`.
- Перезагрузка редактора восстановила название «Проверка черновика браузером», масло, количество `15` и `ml`; уведомление явно сообщает о восстановлении. Рецепт в рабочую базу не сохранялся.
- В консоли проверенной сессии нет ошибок и предупреждений.

Просмотренные снимки: `.local/browser-artifacts/dashboard-after-desktop.png`, `discount-error-mobile.png`, `component-picker-tablet.png`, `discount-200-text.png`. Снимок `dashboard-before.png` сохраняет исходное состояние. Файлы могут содержать только тестовые данные и не включаются в репозиторий.

Автоматические проверки: 243 теста pytest прошли; 20 проверок draft-editor и 11 component-search прошли; синтаксис `app.js` корректен. Независимое ревью проверило доступные имена, сохранение span при изменении JS-подписей и сетку скидки; найденный риск переполнения исправлен и перепроверен в браузере.

Итоговый мобильный снимок `dashboard-after-mobile.png` также просмотрен: счётчики перестроены в строки до 480 px, длинные подписи не отрывают последнюю букву. Django system check не обнаружил проблем. Однократный статический скан Impeccable дал 49 advisory-замечаний (42 цвета, 6 размеров текста, 1 радиус), включая ложные чёрные цвета из-за неразрешённого Django static-тега и прежние декоративные стили. CSS передан сканеру отдельно; результат не объявляется чистой проверкой всего дизайна.

Этот прогон не является полной приёмкой v1: не проверены все маршруты, настоящий скринридер и другие браузеры. В браузерах без `text-box-trim` сохраняется обычное центрирование. Отдельно остаются полная приёмка истории цен, все варианты диалогов и пользовательская оценка оптического выравнивания. Более ранние отчёты о недоступном браузере описывают состояние на дату тех проверок.
