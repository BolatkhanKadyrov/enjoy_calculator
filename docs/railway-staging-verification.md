# Railway staging: проверка первого выпуска

Дата: 5 ноября 2026 года. Владелец разрешил первый оплачиваемый запуск отдельного тестового окружения. Адрес: **https://web-staging-cec3.up.railway.app**. Здесь только созданные проверкой тестовые позиции. Рабочая локальная БД и существующие проекты Railway не изменялись. Пользовательская приёмка и перенос рабочих данных ещё не выполнены.

Дополнение 07.11.2026: этот отчёт сохраняет состояние первого staging-выпуска. Плановое обслуживание 6 и 7 ноября состоялось в 02:00 UTC: оба запуска завершены `EXITED`, ошибок в логах нет. 7 ноября удалён один истёкший технический счётчик входа; блюд и подготовок восстановления удалено 0. По последующему выбору владельца **«Начать с пустой базы»** создано отдельное [рабочее окружение](railway-production-verification.md). Данные staging не переносились и не очищались; дальнейшие вводимые пользователем записи не относятся к исходной тестовой фикстуре ниже.

## Выпущенная версия и ресурсы

- Приложение 0.7.0, GitHub commit **`25194d7a3a4fcae67f3736c0790ca99b6dbbda4d`** у web и maintenance. Последующие изменения этого отчёта не означают новый выпуск приложения.
- Перед публикацией отчёта независимая проверка API подтвердила: автоматический deploy у web и maintenance выключен, список deployment triggers проекта пуст. Push документации сам по себе не является процедурой выпуска; новый релиз нужно запускать и проверять отдельно.
- Проект `enjoy-calculator`, окружение `staging`, регион Amsterdam (`ams`). Автоматически созданное окружение `production` пустое: нет экземпляров сервисов, томов и развёртываний.
- `web`: одна реплика, лимит 1 CPU / 1 ГиБ, Dockerfile, Gunicorn, `python scripts/predeploy.py`, health `/health/` с тайм-аутом 300 секунд; общий predeploy timeout также 300 секунд. Реальный PID 1 работает с UID/GID 10001.
- `Postgres`: официальный `postgres:17.11-bookworm`, одна реплика, лимит 1 CPU / 1 ГиБ. Постоянный том 5000 MB смонтирован в `/var/lib/postgresql/data`, фактический PGDATA — `/var/lib/postgresql/data/pgdata`. Публичных HTTP-доменов и TCP proxy БД нет.
- `maintenance`: одна реплика, лимит 1 CPU / 512 МиБ, тот же commit, команда `sh scripts/start-production.sh maintenance`, Restart Never, без домена, тома и повторных predeploy-миграций.
- Соединение с БД — через private network. Приложение использует отдельную роль `tseh_app` без superuser, CREATEDB, CREATEROLE и REPLICATION. Административный пароль отличается от пароля этой роли.
- DEBUG выключен, hosts/CSRF перечислены явно, HTTPS redirect включён. Случайные секреты и пароль тестового пользователя не входят в Git. Тариф и общий лимит workspace не изменялись.

## Сквозная проверка через браузер

Использован Chrome через Playwright MCP, отдельный профиль и точное разрешение staging origin. Действия выполнены через настоящий HTTPS-интерфейс. До начала проверки доменные таблицы и список пользователей были пусты; применены все 27 миграций, `migrate --check` не обнаружил ожидающих изменений.

Контрольные значения рассчитаны вручную до сравнения с приложением:

1. «Тест: мука»: 1000 ₸ за 1 кг, первичные потери 20%, без поставщика. Чистое сырьё стоит `1000 / 0,8 = 1250 ₸/кг`.
2. «Тест: основа»: 800 г чистого сырья, выход 0,8 кг. Замес стоит 1000 ₸, единица заготовки — 1250 ₸/кг.
3. «Тест: контейнер»: упаковка 20 ₸/шт., без поставщика.
4. «Тест: порция с упаковкой»: 200 г заготовки + 100 г сырья + 1 контейнер. Ожидаемая себестоимость `250 + 125 + 20 = 395,00 ₸`. При цене 1000 ₸ доля составляет **39,50%**. Единственный вид сырья учитывается один раз через все ветви, упаковка исключена: уникальность **100%, 1/1**.

Предпросмотр, сохранённая карточка, повторное открытие и список блюд показали эти значения. Проверены поиск компонента, автоматические единицы г/шт., добавление и удаление строки кнопкой, восстановление названия, выхода и трёх строк рецептуры после F5. Ошибок JavaScript в проверенном сценарии не зарегистрировано.

На ширинах 1440 и 360 px просмотрены карточка и основные действия. Независимый UI-агент не обнаружил существенных визуальных дефектов на этих снимках; кнопки соответствуют варианту C. На 360 px документ не выходит за viewport, таблица состава прокручивается внутри: ширина 322 px, содержимое 387 px, достигнут правый предел 65 px. Стоимость и итог 395,00 ₸ видны на дополнительном снимке. Это не полный аудит WCAG и не проверка всех экранов.

## HTTPS и доступ

Независимый агент проверил внешними запросами:

- HTTP → HTTPS 301; login и health по HTTPS — 200.
- HSTS `max-age=31536000`, `nosniff`, `DENY`, `same-origin`; закрытые ответы имеют `no-store/private`.
- 16 закрытых маршрутов, включая JSON/XLSX, без входа возвращают 302 на login с пустым телом.
- Семь хешированных CSS/JS-файлов доступны, с gzip и immutable-кешированием.
- Поддельный `X-Forwarded-Proto` не создаёт цикл перенаправлений.

Координатор дополнительно проверил Secure/HttpOnly/SameSite=Lax у сессии и Secure/SameSite=Lax у CSRF cookie. Значения cookies не публиковались. Десять неверных попыток входа заняли квоту, одиннадцатая вернула **429 с Retry-After**; действующая сессия продолжала работать. Подмена `X-Real-IP` и `X-Forwarded-For` не создала отдельные квоты. Хеш ключа единственного счётчика совпал с реальным source IP из Railway edge-лога, а не с подставленными адресами или fallback. Адреса и ключи не включены в репозиторий.

JSON и XLSX скачаны через интерфейс staging. JSON прошёл штатную проверку структуры без соединения с БД. Состав: 1 блюдо, 3 строки блюда, 1 заготовка, 1 строка заготовки, 2 покупные позиции, 2 цены, 2 применения цен, 8 событий журнала. XLSX содержит 12 листов; независимые литеральные ожидания 395, 1000, 100% и 39,5% совпали с ячейками. Визуальная проверка книги в Excel в этом запуске не выполнялась.

Расписание maintenance — `0 2 * * *`, 07:00 Asia/Qyzylorda. Явный Run Now завершился 05.11.2026 с 12:05:27 до 12:05:33 UTC, статус API `EXITED`, длительность 5,718 секунды; ошибок в логах нет. Просроченных блюд, подготовок восстановления и счётчиков входа удалено 0. API не предоставляет отдельный числовой exit code. Первый автоматический запуск назначен на **06.11.2026 02:00 UTC** и пока не наблюдался. Обслуживание не создаёт резервных копий.

## Полная копия и сохранность тома

Полный `pg_dump --format=custom` скачан отдельно от контейнера. Размер — 74 454 байта; SHA-256 серверного и локального файла совпадает: `e05e5c2c7fe967a2638e43436aa644e984bddb5e92ff7316f13329f4ac913063`. Согласованные манифесты данных до и после копирования совпали. Dump содержит также технические таблицы и хеш пароля тестового пользователя, поэтому не публикуется.

Независимый агент восстановил dump в новую временную локальную PostgreSQL 17 через `pg_restore --single-transaction --exit-on-error --no-owner --no-privileges`. Проверено:

- Все **26 таблиц, 165 строк**: количества и SHA-256 канонических строк совпали с исходными. Значения последовательностей совпали; 12 последовательностей дополнительно проверены на отсутствие коллизии следующего PK.
- Все 107 ограничений присутствуют и validated. У 97 определения совпали побайтно. Для 10 CHECK PostgreSQL при dump/restore переписал приведение массива `varchar[] → text[]` в приведение каждого строкового элемента. После узкой нормализации только этой формы остальные части определений совпали точно. Обе исходные и восстановленные формы дополнительно проверены 86 read-only пробами допустимых, недопустимых значений, другого регистра и NULL в проверочной PostgreSQL. Различие представления не объявляется побайтным совпадением схемы.
- Миграция `0012_login_throttle`, ревизия домена 5 и независимый контроль себестоимости **395,00 ₸** подтверждены. Все созданные пробные БД удалены; рабочая локальная и QA-базы не менялись.

После успешной проверки копии контейнер PostgreSQL заменён через redeploy существующего образа, без `--from-source`; новый deployment `cb094c84-455b-45b6-a808-04ce8ab18835` имеет статус SUCCESS. Полный манифест до и после замены совпал побайтно, SHA-256 `8f1fd0c877bfa406533206548ab1517dbdb239f5511c98e863019418db643b16`: данные, ограничения и последовательности сохранены. PGDATA остался внутри прежнего постоянного тома; независимая проверка API подтвердила тот же volume, mount, размер и digest PostgreSQL. Затем перезапущен web без нового выпуска: прежняя браузерная сессия сохранилась, та же карточка вернула HTTP 200 и **395,00 ₸**, ошибок JavaScript нет. Новый процесс снова работает с UID 10001, внутренний health с разрешённым Host Railway возвращает `ok`.

## Границы готовности

Staging доступен для пользовательской приёмки. Production и перенос рабочих данных требуют отдельного согласования после неё. Автоматические резервные копии и внешние уведомления об отказах не настроены; ручная копия на этом компьютере не защищает от его потери. Первый автоматический cron ещё предстоит проверить. По первым минутам потребления нельзя надёжно оценить ежемесячную стоимость.

Локальные артефакты проверки находятся в игнорируемой `.local/railway-checks`: отчёты независимых HTTP/resource/UI-ревью, снимки, экспорт, dump и протокол восстановления. Доступ к staging записан отдельно в `access.txt`; он содержит пароль и не публикуется. Отчёты с данными пользователей, сетевыми адресами и техническими секретами в Git не добавлялись.
