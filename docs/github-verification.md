# Публикация в GitHub и проверка Linux

05.11.2026, версия приложения 0.7.0. По прямому поручению заказчика исходники загружены в его публичный репозиторий [BolatkhanKadyrov/enjoy_calculator](https://github.com/BolatkhanKadyrov/enjoy_calculator), ветка `main`. Это отдельное разрешение на GitHub; размещение приложения в Railway не выполнялось.

## Что опубликовано

Первый коммит содержит 206 файлов: код, шаблоны, статику, миграции, тесты, исходные требования, решения, отчёты и инструкции. Перед отправкой выполнена независимая проверка состава и секретов. `.local`, `.venv`, `.env`, рабочая БД, копии PostgreSQL, ключи и браузерный профиль исключены. `.env.example` содержит примеры; фиксированные значения в CI относятся только к одноразовой тестовой базе. Рабочие данные в ходе публикации не менялись.

Добавлены `.gitattributes`, workflow `.github/workflows/ci.yml` и `scripts/ci-smoke.sh`. Actions закреплены SHA, права workflow ограничены `contents: read`, checkout не сохраняет credentials. Ни registry, ни Railway workflow не изменяет. Скрипт контейнерной проверки создаёт собственную PostgreSQL и удаляет только принадлежащие запуску контейнеры/сеть, сверяя имена и метки.

Первые два запуска выявили ошибки нового CI: YAML трактовал двоеточие в однострочной pip-команде как синтаксис mapping, а первый запрос готовности мог попасть между открытием порта и готовностью Gunicorn. Команда переведена в YAML-блок; только цикл начальной готовности повторяет временные сетевые ошибки с ограниченным числом попыток. Последующие проверки ответов остаются строгими. Бизнес-код приложения не менялся.

Для проверенной сборки журнал фиксирует:

- Базовый `python:3.14.6-slim-bookworm`: `sha256:4c92ffcde4dd6f1ff72a24518f49fd4990b27134987dfa31a733badde66df9f8`.
- Локальный image ID результата: `sha256:8050e2ace1758789148e0f0c8511b689de37e01d05e2018d97723e8c5e6d0d9a`.

Image ID относится к временному образу runner, а не опубликованному registry artifact. Dockerfile по умолчанию использует тег базового образа, который может обновиться; для выбора проверенной базы предусмотрен `--build-arg PYTHON_IMAGE=python:3.14.6-slim-bookworm@sha256:…`. Побитовая идентичность будущей пересборки не заявляется.

## Оставшиеся проверки

CI моделирует доверенный HTTPS proxy-заголовок; настоящий публичный TLS/ingress Railway здесь не участвует. Отдельно остаются подключение и согласование размещения, проверка фактических заголовков/host/health, ежедневного расписания и внешних резервных копий с пробным восстановлением. Инструкция — [railway.md](railway.md).

Пользовательская приёмка, просмотр XLSX в настоящем Excel/LibreOffice, полный screen-reader обход и нагрузочное испытание не заменены этими тестами. Локальные браузерные проверки и числовые эталоны описаны в [отчёте этапа 7](stage-7-verification.md) и [матрице приёмки](stage-7-acceptance-matrix.md).
