# Этап 1 — результат проверки

Дата: 04.11.2026. Статус: принят заказчиком сообщением «пока всё работает четко»; полная v1 ещё не готова. Ниже сохранены результаты технической проверки перед этой приёмкой.

## Что выполнено

- Django/PostgreSQL, локальный запуск, фиксированный список зависимостей.
- Защищённый вход, несколько сессий, CSRF, отсутствие публичной регистрации и встроенного пароля.
- Поставщики, ингредиент с первой обязательной ценой, событие применения.
- Блюдо с несколькими ингредиентами; предварительный расчёт, подтверждение, сохранение, повторное открытие и сравнение изменения рецептуры.
- Точные количества, преобразование г/кг и мл/л, первичные потери, суммирование до округления.
- Журнал с читаемыми значениями и снимками, транзакционная запись, ревизии и идемпотентность.
- Исходные требования и последующие решения сохранены в docs.

## Фактически выполненные проверки

Финальный запуск: **57 passed in 10.83s** на реальном PostgreSQL 17.11. Проверки Django: `System check identified no issues`. Проверка расхождений моделей и миграций: `No changes detected`.

Покрытие:

- Буквальные числовые примеры критериев 01–03 и 07, включая 266.67, 1.005→1.01, 30.012→30.01, малую промежуточную цену.
- Дополнительная граница периодического деления 0.01 / 3 × 16.5 = 0.055→0.06.
- Настоящие HTTP-формы: создание поставщика, ингредиента, предпросмотр, сохранение и повторное открытие блюда.
- Подтверждение привязано к составу предпросмотра; подмена требует нового сравнения.
- No-change редактирование через формы сохраняет 0.004000000001 кг, отображение 4.000000001 г.
- Ограничения ввода, несовместимые единицы, отсутствие частично сохранённых сущностей.
- Откат при отказе записи аудита.
- Обязательная действующая цена и её принадлежность ингредиенту проверяются PostgreSQL при commit.
- Два конкурентных соединения: конфликтующая запись отклоняется; одинаковое подтверждение фиксируется один раз.
- Устаревшая форма после изменения зависимостей и поколения данных отклоняется.
- Защита страниц входом, несколько сессий, CSRF, экранирование текста и журнал только для чтения.
- Миграция 0001→0002 сохраняет существующую запись; составной FK остаётся отложенным.
- SSL-параметры из DATABASE_URL сохраняются.

## Независимое ревью

Три агента проверили требования к этапу, арифметику и сохранность данных. Исправлены и повторно проверены:

1. Потеря младших цифр при вычитании очень больших окончательных Decimal в предпросмотре. Теперь точное вычитание Fraction, регрессия проверяет буквальную ожидаемую разницу.
2. Затирание SSL-параметров PostgreSQL при добавлении connect_timeout. Теперь параметры дополняются; есть отдельная регрессия.
3. Формулировка README о pg_dump уточнена: копия базы приложения, роли отдельно.

## Что ещё не подтверждено

- Визуальный и интерактивный прогон в браузере на компьютере и телефоне: browser access host недоступен; доступ к окну Chrome завершился таймаутом подтверждения. Автоматические HTTP-тесты не заменяют эту проверку.
- Пользовательская приёмка первого сценария из README.
- Railway, production Linux и полная v1. Подготовка окончательного размещения — этап 7.

Для QA использовалась отдельная локальная база tseh_qa; доменные данные в неё не добавлялись. Временный QA-аккаунт и сервер убраны после проверки. Основная tseh не заполнялась тестовыми данными. Для приёмки запустите команды README и создайте свою общую учётную запись.
